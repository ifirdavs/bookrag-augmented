# Implementation decisions

Updated 2026-10-15 (Asia/Tashkent).

- Work directly in the requested Git checkout. No commits, pushes, or external publication were made.
- Keep code small and direct: no recursive config inheritance, custom CLI wrappers or unused future-phase schemas/settings. Experiment files override fields from the default config; later features add their configuration when implemented. The CLI handles errors once at its entry point, and parser/index identities share one implementation. Run IDs use standard UUIDs.
- Python 3.13.1, `src` packaging, `uv.lock`, Pydantic, YAML, PyMuPDF, SQLite, and persistent Chroma form the Phase 0–2 implementation. Exact transitive versions are pinned by the lockfile. No orchestration framework is needed for a fixed baseline.
- Generation uses Claude Haiku 5.5 (`claude-haiku-5-5`) through the Anthropic SDK. A small live structured-output call passed. Embeddings use Voyage 4 Large at 2048 dimensions through the official SDK, with the same model for documents and queries. This prioritizes retrieval quality for a small scientific corpus and keeps experimental comparisons consistent. The configured key routes to MongoDB Atlas; small embedding and rerank-3 calls succeeded. The initial trial throughput limit was resolved after the user added a payment method; all 657 chunks are now indexed and saved-index reuse passed. See [model setup](models.md).
- Course-rubric and video requirements are removed. The confirmed 20-paper corpus is sufficient for current development; expand only for relevant coverage gaps.
- MCP is outside implementation scope. The agent will use direct retrieval function calls; an external-client MCP wrapper is only a possible future extension.
- Failure reports include actual observed failures and limitations, with no minimum count and no deliberately induced project failures. Negative questions test successful abstention.
- Credentials are read from environment variables or the ignored project `.env`. `doctor --live` checks Atlas embeddings/reranking and Claude generation; `doctor` makes no API calls.
- Embedding cache keys include provider identity, model, dimensions, tokenizer, chunk ID and text. Versioned indexes include PDF hashes, parse IDs, metadata fingerprints and chunk fingerprints. Active indexes are selected only after a complete build; a completed index is reused without mutation.
- Use fixed 600-token windows with 100-token overlap for B0. The `cl100k_base` tokenizer is explicit. Chunks can cross section/page boundaries; evidence returns every contributing section and page. BM25, section-aware chunking, hierarchy expansion, graph traversal and the direct-function agent remain later phases. Optional rerank-3 is implemented now and disabled in the baseline. Unsupported modes/configurations fail validation.
- A `Block` retains extracted original text and a compact character mapping through whitespace cleanup/dehyphenation. Source spans are half-open Unicode character offsets into that original text. PDF pages are 1-based; printed page labels are additional metadata. These are extraction offsets, not byte positions in the PDF file.
- PyMuPDF reading order is corrected for common two-column layouts and wide separators. Numbered small-cap headings are supported. Uncertain front matter gets an explicit fallback section. These are heuristics and require sampling; no claim of perfect semantic structure is made.
- Keep original table/equation blocks in canonical documents, but exclude detected table cells and equation-like fragments from baseline chunks. Horizontal-rule tables below captions are flagged even when PyMuPDF's default table detection misses them. Captions can provide prose evidence; chart pixels and unvalidated numeric cells are not interpreted. Some borderless tables or equations can evade detection.
- Assume the 20 PDFs already exist locally. The manifest keeps only paper ID, title, year, source URL, document version, SHA-256 and method names. Corpus download/search commands are removed. Baseline retrieval searches all chunks unless the caller supplies a filter; automatic paper routing and query rewriting are disabled.
- A shared `RetrievalService` validates filters, enforces candidate/evidence budgets, and removes substantial overlapping source spans. It records dense cosine scores and, when enabled, separate reranker relevance scores; neither is treated as a calibrated answerability probability. The generator judges sufficiency from the packed evidence; no arbitrary similarity threshold is claimed to solve abstention.
- Structured claims cite known evidence IDs. Code checks citation existence and source provenance; semantic claim support, answer correctness, and abstention require review. An unknown citation rejects the answer instead of silently repairing it. No agent planner is involved.
- Benchmark annotations are selected directly from canonical source blocks, independently of retrieval. Exact quotes and raw character spans are validated without a dense index or API credential. Held-out execution requires a frozen file hash after source verification; the freeze records whether independent human review occurred. Automated span-overlap metrics remain diagnostics until required-fact matches have been adjudicated.
- USD cost fields remain null unless the user supplies deployment pricing. Usage token counts and request counts are recorded. No rate-limit, cost, or quality claim is made without live measurements.

Documentation consulted: [Claude Haiku 5.5](https://platform.claude.com/docs/en/models/haiku-5-5/overview), [structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [Voyage embeddings](https://docs.voyageai.com/docs/embeddings), [Chroma clients](https://docs.trychroma.com/reference/python/client), and [PyMuPDF text extraction](https://pymupdf.readthedocs.io/en/latest/recipes-text.html).

- Document every source/test function, marking small supporting functions with `Helper to ...:`. The README Python file guide explains each real module and its purpose. Temporary `docs/` notes will be consolidated into the README/final reports and removed in Phase 8.

- The first live development answers added unnecessary theory/proof qualifications. The answer prompt was refined once to focus on requested facts and assess sufficiency against the question; the earlier and final run identities are retained in the evaluation report. Held-out labels/questions were not used for this change.
- Initial B0-R diagnostics replay the exact saved B0 candidates, with identical IDs/order/scores, so query-time retrieval variation does not confound the reranking check. These are five-question development span diagnostics; semantic quality still requires adjudication.
